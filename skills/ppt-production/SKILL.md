# PPT 制作与验收

保留用户指定的交付格式、内容范围和已确认样式。本技能提供可按项目覆盖的默认偏好；用户当次要求优先，具体模板、配色和本机路径以项目 AGENTS.md 为准。

## 工作顺序

1. 确认当前稿、修改范围及参考文件用途。固定模板保留母版与主题；素材合集只取需要的局部结构。首次使用模板时测量画布、字体和页眉页脚边界，见 `references/measure-template.md`。
2. 修订已有稿先读取 `references/editing-and-verification.md`，核对目标对象并备份，再做小批量定点修改。编辑或保存失败先解决，不能继续导出旧稿并当作新结果。
3. 迭代时渲染改动页，按 `references/layout-checklist.md` 打开图片检查。交付前整本通读，确认跨页一致性；本次没有重新打开的页不得声称已重审。
4. 运行 `python <skill_dir>/scripts/pptx_audit.py <deck.pptx> --min-pt 20` 辅助检查。导出成功、PNG 文件存在、审计退出码 0 都不是视觉通过的证据；明确可见的溢出或遮挡必须修复后再交付。

## 区域结构化与素材取用

文字、图片、表格按共同含义组成结构单元，再用对比、因果、流程、总分或证据汇聚组织整页。优先采用适合内容的“标题—框—内容”，不固定区域数量，不机械套卡片网格。

制作、改版及组图排版时读取 `references/regional-structure.md`。先读项目指定或随附的 `assets/library/index.md` 筛选候选，再查看对应预览与原生源文件；新增或刷新素材时读取 `references/library-workflow.md`。素材库是结构范例，不自动规定新稿的主题、数据或科学结论。

## 内容与排版

- 正文、表格、图注默认至少 20 pt，页码沿用模板。放不下先调整文字、分区或分页，不偷偷缩字号。图片中的小字按用途判断：论证依赖的标注要清楚，展示资料或工作量的缩略图可保留，关键结论用可读的原生文字另列。
- 强调观众要理解的对象、成果或判断；报价方、来源等通常作为次级信息。整页共有的范围说明写一次。长标题、金额与来源宜分区，改变文案或加粗后重新验证换行和边界。
- 同级区块的边距和间距应稳定；区块之间的间距与区块内部行距分别处理。框体贴合内容，不为填满页面而拉长卡片或撑大段间距；不把某页的英寸值固化为通用规则。
- 组图统一图片显示区域、图注基线和字体格式，保留原图比例；尺寸细节见 `references/regional-structure.md`。
- 汇报稿应可独立理解，去掉依赖私人台账的内部术语。用户要求突出成果时，概括已有结果和后续方向，不添加未经确认的完成日期、承诺或待老师解答的问题。内容较少的末页可在授权范围内提炼已证实成果，不为补空白虚构新进展。
- 内部汇报封面通常只留标题、报告人、时间；正式答辩遵循指定模板。金额与同级正文保持相近字号，强调不只靠放大。

## 编辑中的易错项

- 状态优先用文字表达，避免易缺字的装饰符号；数学符号与希腊字母保留并检查实际字形。讲稿、时间分配与讲述提示留在备注中。
- 表格按实际字体、换行与内边距确定高度；删掉或缩短区域后检查相邻内容与留白，不沿用失效的旧位置。

- `shape_id`、形状名称末尾数字、集合索引是不同标识；名称也可能重复。修改前同时核对对象类型、文本和几何，具体做法见 `references/editing-and-verification.md`。
- 项目符号可能是原生段落设置，也可能是独立文本 run；先查看实际结构。页码还可能存于 `a:fld`，普通 `runs` 为空不代表没有文字。
- 同时设置拉丁字体和东亚字体；XML 使用完整命名空间，元素存在性用 `is None`。不要猜 API 或直接写未验证的锚点值；渲染异常时回到简单、可验证的排版方式。
- 优先保持已正确的图层关系；组合内部的背景应在文字与图片后方。允许有意叠放，但必须确认文字可见、对比度足够、没有遮住关键内容。
- 页码按实际底色和边界检查，可以在底栏内高对比显示，也可以放在栏外安全留白中；不规定一律向右下移动。空占位符与肉眼可见的模板提示文字要区分。

## 导出与渲染

随附脚本将 PDF 导出和逐页 PNG 生成合并为一次调用：

```powershell
# 在 PowerShell 会话中调用；Pages 是数组。
& <skill_dir>/scripts/render_deck.ps1 -Pptx <deck.pptx> -OutDir <render-dir> -Pages 3,8
```

Windows 可选择 PowerPoint/WPS COM；其他环境可使用已安装的 LibreOffice（`-Engine soffice`）再由 Poppler 栅格化。`pdftoppm` 可通过 `-Pdftoppm` 指定，也可由 PATH 等位置发现。具体能力以实际安装及导出结果为准，Word COM 不承担 PPTX 导出。

- 按执行环境的权限机制处理 COM 错误；一次机器上的沙箱或注册错误不能推广为所有机器必然失败。只有确定是权限问题时申请相应权限。
- 优先使用可重复的导出入口；GUI 也可作为可验证的回退，但必须检查保存格式、目标文件及加载项弹窗，不能把 `.ppt` 当作 `.pptx`。
- 导出只关闭本次打开的文稿；若不能确认应用实例独占，不调用全局 Quit，也不结束用户的 Office 进程。随附脚本的 COM 分支包含 Quit，使用前确认不会关联用户的其他文稿；不满足时改用能保留该会话的导出入口。
- 每轮使用独立或明确专用的输出目录，避免混用旧图；随附脚本会清理该输出目录中的 PNG，因此不可指向用户素材目录。换渲染器或字体后重新检查受影响页面。

## 审计与交付

`pptx_audit.py` 支持 `--json`、`--overlap-threshold 0.30`：

- `font-below-floor`：明确字号违规；纯数字正文也受检查，仅真正的页码占位符或字段豁免。
- `font-inherited-review`：未解析到显式或段落字号，需查母版或渲染结果。
- `symbol-glyph-review`、`overlap-review`：待核实提示，既不证明真实遮挡，也不能一概标成“有意叠放”。脚本不做 OCR，不测真实文字换行后的墨迹边界；组内文字会查字号，但不能据此推断组内布局通过。
- 退出码 0 表示未发现明确字号违规，1 表示有违规，2 表示无法检查。

交付前核对最终 PPTX、导出的 PDF 与所读图片来自同一版。说明实际修改、实际检查范围及未解决问题；覆盖原稿前保留备份，文件占用时按 `references/editing-and-verification.md` 处理。
