# PPT 制作与验收

用于 PPTX 制作及排版修改。保留用户指定的交付格式、模板和修改范围；本技能提供可按项目覆盖的默认偏好，用户当次明确要求优先。具体模板、配色和本机路径以项目 AGENTS.md 为准。可与宿主的演示文稿工具配合使用。

## 工作顺序

1. 有参考模板时先测量画布、标题/正文字号、页眉/页脚边界，再排版；见 `references/measure-template.md`。分别报告直接测量、继承属性和未核实项。
2. 先辨明参考文件用途：用户指定为整套模板时，从副本保留母版/主题；若为优秀 PPT 素材合集，按语义选用局部结构，统一到目标稿样式，不默认继承整库主题或清空素材源。修订现有稿沿用已确认样式，仅改指定范围。
3. 完成后导出 PDF 并逐页转图，打开每一页检查；清单见 `references/layout-checklist.md`。发现问题后修改、重新渲染受影响页。
4. 运行 `python <skill_dir>/scripts/pptx_audit.py <deck.pptx> --min-pt 20` 辅助检查。最终交付须说明渲染和检查是否完成；渲染受阻只能称为未验收草稿。

## 区域结构化与素材取用

采用用户的区域结构化偏好：文字、图片、表格先按共同含义组成有职责的结构单元，再通过对比、因果、流程、总分或证据汇聚组织整页逻辑，最后统一对齐、间距、颜色与视觉主次。优先选用素材库中的“标题—框—内容”结构，避免游离小文本；原生透明文本框可作为区域内部元素和图像标注。结构应服务内容，不固定区域数量或把每页套成同样的卡片网格。

制作或改版时读取 `references/regional-structure.md`，其中包含取用流程、验收问题及随附素材库入口。先读 `assets/library/index.md` 筛选候选，再查看对应预览和原生源文件；新增或刷新素材时读取 `references/library-workflow.md`。用户当次指定的设计优先；本机素材库不可访问时说明限制。素材库提供局部结构和逻辑范例，不自动规定所有项目的主题、颜色或科学结论。

## 内容与排版偏好

- 正文、表格、图注默认至少 20 pt；页码保留模板大小。放不下先精简或拆页，具体场景的例外由用户指定。引用图片中的文字另行读图检查，脚本不做 OCR。
- 独立内容区域不得互相遮挡、越界或压住页眉线。背景、图片标注和组合内部的有意叠放允许存在，以渲染结果是否清晰为准。
- 框高贴合内容，保持稳定内边距；避免一行文字占三行高度和大量无目的留白。
- 避免装饰性的“三点式并列小字”；用完整句或分行短句。讲稿、时间分配、强调提示留在备注，不写进正文。
- 内部汇报封面通常只留标题、报告人、时间；正式答辩遵循指定模板的导师、单位等字段。
- 金额和数量与正文同档字号，不为强调而额外放大。

## 渲染前的易错项

- 状态用“首选/已排除/谨慎”等文字表达，避免勾叉、警告、星号等容易缺字的图形字符。数学符号、希腊字母正常保留，读图确认字形。
- 同时设置拉丁字体和东亚字体。编辑 XML 时使用完整命名空间；判断元素是否存在用 `is None`，不要用空 XML 元素的真假值。
- 标题标签放在合适的绘制层，避免后添加的图片遮字；不为了图层顺序让标签压住页眉线。
- 表格按实际渲染高度留空间。20 pt 行高约 0.44–0.55 in 只能作起点，字体、换行、内边距都会改变它。
- 检查复制版式后页码是否存在、位置是否可见；空标题占位符可合法保留。清除肉眼可见的示例文字和未完成标记。

## 导出与渲染

入口一条命令（Windows）：

```
pwsh -NoProfile -File <skill_dir>\scripts\render_deck.ps1 -Pptx <deck.pptx> [-OutDir <dir>] [-Pages 3,8] [-Dpi 120]
```

脚本先尝试 `PowerPoint.Application`、`Kwpp.Application` 的 COM（`SaveAs(pdf, 32)`），再用 `pdftoppm` 栅格化成 `page-N.png`，只负责把“改完能出图”变成一条命令，不等于验收。`pdftoppm` 按 `-Pdftoppm` 参数、`PATH`、常见安装位置依次查找；装了 LibreOffice 的环境可传 `-Engine soffice` 走无界面转换，不依赖 COM。

- COM 导出在受限沙箱里通常失败，并且两种引擎的报错不同：PowerPoint 常见 `80070520`（登录会话不存在），WPS 常见 `80040154`（类未注册）。同一台机器放开权限后往往都能用；别在受限环境里反复试 ProgID，直接申请权限或改走 `soffice`。
- **不要用 GUI 的 文件→导出 / 另存为** 做批量验收。加载项弹窗会打断流程，“保存类型”下拉用键盘切换也容易失效，实测可能把稿子误存成 `.ppt`（兼容性模式）并锁住文件。
- macOS / Linux 没有 COM，用 `soffice --headless --convert-to pdf` 再 `pdftoppm`；同一份稿在不同渲染器下的字体替换可能不同，换过渲染器要重新读图。
- 导出时保留用户正在编辑的文稿，不关闭他人的窗口；脚本自己 `Close()` + `Quit()` 它开的实例。

## 修改与验收循环

单页改版按这个节奏，不要每轮全量重读：

1. **备份**：改前 `copy` 一份 `<name>_before_<意图>.pptx`。文件名写清意图（`_before_slide3_layout_fix`），比 `_v2` 有用。
2. **改**：python-pptx 按 `shape_id` 定点改；先 dump 该页所有形状的 `id / 位置 / 尺寸 / 填充 / 文本` 再动手，别猜。
3. **渲染**：`render_deck.ps1 -Pages <改过的页>`，只出改动页。
4. **读图**：逐张看，按 `references/layout-checklist.md` 走；改动跨页语义（目录、页脚、章节编号）时**额外整本通读一遍**。
5. 有问题回到第 2 步；通过后保留 PDF 一并交付。

两种读图粒度都要：

- 迭代时只读改动页，省时间省上下文。
- 收尾时整本通读，抓单页看不出的问题：目录条目与正文标题不一致、DESIGN 文档写的配色与实际不符、同一层级卡片在不同页用了不同强调色。

## 易错项（实测踩过）

- **项目符号是独立的文本 run，不是段落属性**。`·` 常被写成带颜色的第一个 run（`<a:rPr><a:solidFill>`），复制 `pPr` 改不动它；要改 `paragraphs[0].runs[0].font.color`。判断依据是渲染图里符号颜色仍异常。
- **卡片高度要贴合内容，不能为了填满页面而拉高**。三条 20 pt 项目符号在 2.4 in 高内刚好；拉到 5.9 in 会把内容推到中间、上下各留一大块空。宁可让页面下方留在版心外，也不要在框内留洞。
- **删掉重复的总结块后要重排**，否则会留下原位置的空带和浮在页脚的条。
- 空标题占位符可以合法保留，但肉眼可见的“单击此处添加标题”必须清掉；清完对母版再确认一次。

## 审计

`scripts\pptx_audit.py <deck.pptx> --min-pt 20` 支持 `--json`、`--overlap-threshold 0.30`：

- `font-below-floor` 为明确字号违规；纯数字也属于正文，只有真正的页码占位符/字段豁免。
- `font-inherited-review` 表示未解析到显式/段落字号，需查母版或渲染结果，不能当作通过。
- `symbol-glyph-review`、`overlap-review` 仅提示检查，不证明缺字或真实遮挡。重叠只比较顶层有效内容区域，忽略空占位符、纯装饰和整页底图；组内文字仍查字号。
- 退出码 0 只表示未发现明确字号违规，1 表示有违规，2 表示无法检查；**0 不等于视觉验收通过**，包围框检查不替代溢出、压线、组内布局和逐页读图。

覆盖已有交付文件前保留备份；布局修订默认保留原文，涉及内容变化时以用户指定范围为准。
