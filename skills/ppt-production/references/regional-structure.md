# 区域结构化：个人 PPT 设计原则

用户将优秀 PPT 中的结构持续收集到可编辑素材库。目标是让观众一眼读出“这些元素属于哪个意思，这些意思如何组成整页”。素材库是一组可取用、可改造的结构范例，不是所有页面必须套用的统一主题。

## 三层组织

1. **结构单元**：把讲同一件事的标题、文字、图片、图注、表格等聚合成一个可辨认区域。标题说明区域负责回答的问题；内容提供证据/解释；必要时给局部结论。取用“标题—框—内容”的组合时保持其整体关系，不只复制一个边框。
2. **页面逻辑**：给每个结构单元安排角色，按对比、因果、流程、总分、证据到判断等关系组织。先确定整页要说明的主题或结论，再决定需要多少区域、每个区域放什么。元素数量不决定区域数量。
3. **平面整合**：以共同网格、对齐、间距、色彩、字体层级和视觉重心把区域合为完整画面。区域之间的逻辑应可见，阅读顺序应清楚；结构数量、大小和位置跟随内容，不能为凑对称或填满页面添加空洞模块。

## 实际选择

- 用户偏好有格式的标题—框结构，优先从素材库选适合当前语义的组合。只有在清楚归属于某区域、图像标注或全页标题/结论时，才保留独立的透明文本框；避免文字、图、图注漂散在页面。
- 区域可通过标题条、边框、底色、对齐或邻近关系识别，未必每层都画框。视觉区域是语义分组，和 PowerPoint 内部是否 Group 不是同一件事。
- 同级区域采用一致视觉语法；不同角色可以不等宽、不等高。重要关系用布局表达，连接线/箭头只在确有流程或因果时使用。
- 先选结构适配，再统一目标稿的字体、配色、线宽和字号。库中来自不同优秀 PPT 的样式不可原封不动混搭；来源中的小字、标识、科研数据、姓名和配色不自动成为用户规范或事实。
- 一页只有一个完整图区或一张表时，它本身可构成主区域；标题和结论能完成组织时，无需再加多层框。不要把“区域结构化”简化成每页三张同样的卡片。

## Agent 的取用顺序

1. 先读项目指定的素材库索引，检查源文件是否已更新；失效的页码/预览必须重新核对。
2. 用一句工作备注写明整页主题/结论，列出各区域的角色和关系；这些规划不写进幻灯片正文。
3. 按逻辑关系和内容类型筛选少量候选页，打开对应预览，回到原 PPTX 查看原生形状、组合和图层。
4. 区分“直接取用组件”与“参考结构后重建”：前者保留图形关系、图片关系与可编辑性，后者保留语义组织并适配内容。截图仅作索引，不能替代本应可编辑的文字/表格。
5. 完成整页的统一排版，渲染逐页检查。备份和修改发生在输出副本中，不覆盖素材源文件。

## 验收问题

- 每段正文、图片、表格及其图注，能否明确归属某个结构单元？有没有游离的小标签或小文本框？
- 每个区域是否有能说清的职责？同一区域内的元素是否确实在讲同一件事？
- 区域之间的关系是否支持整页主题，是否能按明确顺序读完？有没有只是并排而无关系？
- 全页是否统一对齐、留白、色彩与视觉主次？是否过度套框、平均分配权重、挤字或堆装饰？

## 素材库持续更新

源 PPTX 保持唯一权威来源，索引保存源路径、SHA-256、幻灯片稳定 id、包内 XML 路径、原生形状信息、预览和人工语义标签。新增、删除、改页或移动后检查哈希并重建提取/预览；重新核对语义标签。稳定 id 只在当前 PPTX 内帮助定位，不保证跨文件复制或重建后保持。未检查新页不得标记为已可用。

当素材库未安装或路径不可访问时，按上述原则工作并明确告知无法直接取用；不得声称已读某个范例。项目文件负责保存素材库位置，本技能负责保存可迁移的方法。

## 随附素材库入口

- 源文件：`../assets/library/source.pptx`，为可编辑的结构素材合集。
- 人读索引：`../assets/library/index.md`；可搜索图库：`../assets/library/gallery.html`。
- 机器索引：同目录 `catalog.json` 和 `inventory.json`，预览位于 `previews/`。
- 可在项目 AGENTS.md 中指定另一份素材库，优先于随附示例；使用前运行 `scripts/check_library.py` 校验。
- 查看 `references/library-workflow.md` 了解新增素材、刷新预览及复核步骤。
